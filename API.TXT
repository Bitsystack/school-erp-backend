====================================================================
AUTH  /api/v1/auth
====================================================================

ONBOARDING FLOW (New User from Landing Page):
─────────────────────────────────────────────
  1. POST /register          → User fills name, email, phone, password
                               → Verification email sent
                               → Response: { user_id, user_isEmailVerified: false }

  2. GET  /verify-email?token=  → User clicks link in email
                                 → Auto-login (cookies set)
                                 → Response: { user_hasBusiness: false }
                                 → Frontend redirects to /setup-school

  3. POST /setup-organization  [Auth]
                               → User fills school name, phone, email, country
                               → Organization created + linked to user
                               → New tokens issued (with organizationId)
                               → Response: { organization, user }
                               → Frontend redirects to /dashboard ✅

─────────────────────────────────────────────
POST   /register
  Body: {
    user_name, user_email, user_phone, user_password,
    user_country,
    user_business_type: "School"|"College"|"Coaching"|"University"|"Other"
  }

GET    /verify-email?token=TOKEN
  → Verifies email, auto-login, sets cookies

POST   /resend-verification
  Body: { user_email }

POST   /setup-organization    [Auth — after email verify]
  Body: {
    organization_name, organization_phone, organization_email,
    organization_country, organization_address?,
    organization_pincode?, organization_website?,
    organization_whatsapp?, organization_gstin?, organization_upi_id?
  }

POST   /login
  Body: { user_email, user_password }
  Response includes:
    user_isEmailVerified  → false = redirect to /verify-email
    user_hasBusiness      → false = redirect to /setup-school
    else                  → redirect to /dashboard

POST   /logout             Clears cookies

POST   /refresh-token      Rotates tokens (call when 401)

POST   /forgot-password
  Body: { user_email }

POST   /reset-password
  Body: { token, password }

POST   /change-password    [Auth]
  Body: { current_password, new_password }
  → Clears session, user must re-login

─────────────────────────────────────────────
FRONTEND ROUTING LOGIC (after login/verify):
─────────────────────────────────────────────
  if (!user_isEmailVerified)  → /verify-email
  else if (!user_hasBusiness) → /setup-school
  else                        → /dashboard

DASHBOARD  /api/v1/dashboard
====================================================================
GET    /stats                 [Auth] Full dashboard stats

Response includes:
  - overview (students, teachers, staff, classes)
  - attendance_today (present, absent, percentage)
  - finance (monthly_fee_collected)
  - alerts (pending leaves, open complaints, pending admissions, overdue books)
  - upcoming_exams (next 5)
  - recent_announcements (last 5)

SEED
====================================================================
Run once to create system roles + super admin:
  npm run seed

Default super admin:
  Email:    admin@schoolerp.com  (or SUPER_ADMIN_EMAIL in .env)
  Password: Admin@12345          (or SUPER_ADMIN_PASSWORD in .env)

====================================================================
SYSTEM ROLES
====================================================================
  SUPER_ADMIN        → Full platform access
  ORGANIZATION_ADMIN → Full access to own org
  TEACHER            → Class, attendance, marks, homework
  STUDENT            → View own data, fees, timetable
  PARENT             → View child's data, complaints
  ACCOUNTANT         → Fee & salary modules
  LIBRARIAN          → Library module
  STAFF              → Announcements, events, leaves

====================================================================
NOTES
====================================================================
- All data is scoped by organization_id (multi-tenant)
- Soft deletes used for students, teachers, staff (status = false)
- Bulk operations supported: attendance mark, marks entry
- Auto-generated IDs: admission no, employee ID, receipt no
- Image upload via Cloudinary (teacher photo, org logo)
